# 🔑 THIS IS STILL HAND-MAINTAINED, AND SAYING OTHERWISE WOULD BE THE FALSE CLOSURE THIS
# REPO KEEPS CATCHING. What changed is the number of copies (four -> one) and the strength
# of the check (a count -> a set). Adding a band is still a human writing a line.
#
# 🔴 AND IT MUST NOT BE DERIVED FROM THE BRANCHES. The obvious "fix" -- generate this list
# by globbing mc/** -- makes the comparison len(x) >= len(x) and deletes the guard while
# leaving it looking present. --require-bands exists precisely because that enumeration can
# come back SHORT: a shallow clone, a missing fetch-depth: 0, a rename, absent remote refs.
# An auditor that finds zero bands prints "No drift" and exits 0, which is indistinguishable
# from a clean run. This file is the independent statement that makes that detectable.
#
# WHAT A SET BUYS OVER A COUNT: a RENAMED band keeps the count and breaks the set. The old
# floor could never see it. `expected_bands.py --verify` reports the names, both directions.
#
# ⚠️ master is NOT listed and must not be. It IS the newest supported band (ruling R-a) but
# it lives outside the mc/** namespace that every one of these scripts globs, which is why
# the floor is 8 and not 9. Section 37 measured the failure mode of guessing high:
# --require-bands 9 against eight bands returns EXIT 2 while the very same run still prints
# "No drift" above it. Read the exit code, never the sentence.
#
# ⚠️ Ordering and case are not significant; duplicates and an empty list are refused.
#
# To add a band: cut it per TODO.md's per-band recipe, then add its name here in the same
# commit. To retire one: remove the line in the commit that deletes the branch.
#
# ===========================================================================================
# TWO SECTIONS: LIVE AND ARCHIVED  (TODO.md section 69 phase D, owner ruling 3 of section 69)
# ===========================================================================================
#
# "Archived" means KEEP THE BRANCH, STOP AUDITING IT. It does NOT mean deleted, and it does
# not mean unreleased: every archived band keeps its published v1.4.0 release, marked final
# in the docs. Ruling 2 says fixes propagate to the 26.x bands and mc/1.21.11 only.
#
# Lines before any [section] header are LIVE. That is deliberate: it is the historic format,
# so an older copy of this file parses as all-live rather than as an empty set.
#
#   --count   -> LIVE ONLY. It is the --require-bands floor for audits that now skip the
#                archived bands, and counting archived ones would make that floor unreachable.
#   --verify  -> LIVE + ARCHIVED, both directions, against git. An archived branch is still
#                expected to EXIST. It is simply not audited for drift.
#   --list    -> live.  --list-archived -> archived.  --list-all -> both.
#
# 🔴 THE FILTER IS SET SUBTRACTION BY EXACT NAME, NEVER A PATTERN. A glob or prefix can
# over-match, and a filter that matches too much leaves all four guards auditing ZERO
# branches and printing green -- the vacuity family this repo has now caught sixteen times.
# An exact-name subtraction cannot over-match: the only way to empty the audited set is a
# declaration that visibly names every band, line by line, in this reviewed file.
#
# 🔴 AND A BRANCH IN NEITHER SECTION IS AUDITED, NOT SKIPPED. Fail-closed. A band cut
# without a line here must never become invisible to every guard at once; it is reported
# UNDECLARED by --verify and it is still audited in the meantime.
#
# ⚠️ An unknown [section] header is REFUSED (exit 2), so a typo cannot quietly land lines in
# a section that means "skip me". A name in BOTH sections is refused like a duplicate.
#
